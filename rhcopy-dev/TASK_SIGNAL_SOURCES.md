# Задача: источники сигналов, совпадения и фильтр инсайдеров

Сначала прочитай `AGENTS.md` — там архитектура и правила. Ниже — что добавить в бота: импорт кошельков, сигнал совпадения и фильтр инсайдеров. Колл-каналы Telegram в этой задаче **не делаем**. Работай по этапам: после каждого этапа прогоняй тесты и делай коммит.

Цель — понять, какие источники сигналов реально дают плюс после задержки и комиссий. Поэтому каждый вход должен быть подписан своим источником, а статистика должна считаться по источникам.

## Этап 1. Общая модель «источник сигнала»

Сейчас сигнал всегда приходит от кошелька-трейдера. Нужно: метка у трейдеров, откуда они импортированы (этап 2), и отдельный тип входа «совпадение» (этап 3).

**База данных** (только добавлять, без удалений):
- `traders.source TEXT DEFAULT 'manual'` — значения `manual` / `fomo` / `gmgn` / `kolscan` / `madeonsol` / `paste`.
- `positions.source TEXT DEFAULT 'wallet'` — значения `wallet` / `confluence` (значение `tg` зарезервировано под будущие каналы).
- `signals.source TEXT DEFAULT 'wallet'`.

**Код:**
- В `buy()` записывай `source` позиции.
- **Сообщения о докупках.** Сейчас докупка трейдера (у него уже был баланс токена) молча игнорируется: в EVM это ветка `prev > 0` в `on_incoming`, в Solana — `ev["pre"] > 0` в `on_sol_tx`. Сделай как в copyfomo: записывай её через `log_skip` с причиной `not_first_buy` («не первая покупка трейдера в этой монете») — с суммой докупки, капой и кнопкой «🔕 Не присылать такие». Покупать по докупке по-прежнему не нужно (кроме необязательного этапа 5). Данные DexScreener бери с кэшем, чтобы не тормозить цикл. Если у пользователя уже есть позиция в этой монете, не присылай ничего — это обычное «уже держим».
- Статистика по источникам: 📈 Статистика → новая кнопка «📡 По источникам». Там сводка по типу входа (`wallet` / `confluence`) и по каждой метке импорта трейдеров (`manual`, `fomo`, `gmgn`, `kolscan`, `madeonsol`, `paste`): сколько закрыто сделок, процент прибыльных, PnL.

## Этап 1.5. Сети BNB Chain и Base

Трейдеры FOMO торгуют ещё в BNB Chain и Base, и copyfomo за ними следит, а наш бот — нет. Из-за этого пропускаются сделки (пример: покупка AWEB трейдером iruletrenches была в BNB Chain). Добавь обе сети по той же схеме, что и Ethereum: `EvmNet` в `CopyBot.__init__`, сканирование в `scan_net`, проверка подлинности через Relay, исполнение через Relay.

- **Сети:** BNB Chain (chain id 56, DexScreener `bsc`) и Base (chain id 8453, DexScreener `base`). Проверь в `GET https://api.relay.link/chains`, что Relay поддерживает обе и какие у него там контракты.
- **Стейблкоин сделок и его точность.** Сейчас код считает, что у стейблкоина 6 знаков: `int(ticket * 1e6)` в `judge()` и `executor.buy()`, деление на `1e6` в `sell()`, в `cash()` и в выводе средств. В BNB Chain у USDT и USDC **18 знаков**. Добавь в `EvmNet` поле `usd_decimals` и используй его везде вместо `1e6`.
  - Base: USDC `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` (6 знаков).
  - BNB Chain: USDT `0x55d398326f99059fF775485246999027B3197955` (18 знаков). Сверь адреса с официальными источниками.
- **Список игнорируемых токенов:** стейблкоины и WETH/WBNB каждой сети.
- **Публичные RPC без ключей** со сменой при ошибке, как в разделе `ethereum`. Заранее проверь, что каждый узел отдаёт `eth_getLogs` с фильтром по `topics` без адреса контракта (некоторые узлы так не умеют) и `eth_call` на последние блоки. Свой адрес — переменными `BSC_RPC_URL` и `BASE_RPC_URL` в `.env`.
- **Настройки** в `config.yaml`: разделы `bsc` и `base` по образцу `ethereum`, с подобранными `poll_seconds`, `log_chunk_blocks`, `max_catchup_blocks` (блоки примерно 0.45 с и 2 с), `min_gas_eth` (у BNB Chain газ платится в BNB) и `max_gas_pct`. Обе сети включены по умолчанию в `chains`.
- **LIVE для каждой сети отдельно.** Не плоди колонки под каждую сеть: добавь в `users` одно поле `live_chains TEXT` (JSON-список сетей). Старые `live`, `sol_live`, `eth_live` перенеси в него одноразовой миграцией с флагом в `kv`, а `live_on()` переведи на новое поле. Старые колонки не удаляй.
- **Кнопки:**
  - в 👛 Кошельки — экраны BNB Chain и Base по образцу Ethereum: тот же EVM-ключ, свои балансы, вывод стейблкоина и нативной монеты, отдельный LIVE;
  - в 🌐 Сети — переключатели для обеих сетей;
  - метки сети в позициях и пропусках: `BSC`, `BASE`.
- **Тесты:** сделка с подставленными фактами в каждой новой сети (paper, реальная котировка Relay) с проверкой сумм — особенно 18 знаков у BNB Chain. Обход кнопок и миграция старой базы должны проходить.

## Этап 2. Импорт кошельков: GMGN, kolscan, MadeOnSol

### Импорт вставкой (GMGN, kolscan, любые списки)
- **Не скрапь** GMGN и kolscan — у них защита от ботов. Вместо этого кнопка «📥 Импорт кошельков» в разделе «Трейдеры». Пользователь присылает текст: список адресов, CSV, скопированную таблицу или ссылки.
- Из ссылок адрес достаётся по шаблону:
  - `gmgn.ai/<chain>/address/<addr>`;
  - `kolscan.io/account/<addr>`;
  - `solscan.io/account/<addr>`;
  - `etherscan.io/address/<addr>`;
  - профили MadeOnSol.
- Метку ищи в той же строке: `ник адрес`, `адрес ник` или колонку CSV.
- Метку источника определяй по домену ссылки, иначе `paste`.
- Покажи предпросмотр: сколько адресов, сколько Solana и сколько EVM, первые 10 и сколько дублей уже в списке. Затем кнопка «✅ Добавить N».
- **Solana-адреса** добавляй как Solana-трейдеров: `add_trader` + `set_pair(addr, addr)`, как это уже делает текущий ввод Solana-адреса.
- **EVM-адреса** добавляй как EVM-трейдеров. Для не-FOMO кошельков пара будет пустой — это нормально: их собственные сделки (`tx.from == wallet`) проходят проверку подлинности как `own`.
- **Лимит:** `sources.max_traders_per_user`, по умолчанию 200.

### MadeOnSol API (официальный)
- Ключ `MADEONSOL_API_KEY` в `.env`. Бесплатный тариф — 200 запросов в день.
- **Сначала прочитай документацию:** https://madeonsol.com/api-docs. Есть Python SDK `madeonsol-x402`, но можно работать через REST и `requests`. Эндпоинты не выдумывай.
- Импорт «🏆 Топ KOL из MadeOnSol»: запрос лидерборда KOL, фильтры (период, минимальный процент прибыльных сделок, минимум сделок, top N), предпросмотр с цифрами (ник, процент прибыльных, PnL, число сделок), подтверждение и добавление с `source='madeonsol'`.
- Кэшируй ответы. Одна загрузка лидерборда — один запрос.

### Масштаб слежения (обязательно, иначе импорт сломает слежение)
- **EVM:** в `scan_net` дели список адресов в `topics` на пачки по 100 — у RPC есть лимит на размер массива.
- **Solana:** `SolWatcher` раздели на несколько WebSocket-соединений по `solana.ws_wallets_per_conn` кошельков (по умолчанию 50). Опрос как запасной вариант должен работать для всех соединений.
- В README честно напиши: при сотнях кошельков нужен свой RPC (Helius и т.п.), публичные узлы не выдержат.

## Этап 3. Сигнал совпадения

Вход только тогда, когда **два и больше независимых** отслеживаемых кошелька купили одну монету за короткое окно.

**Настройки пользователя** (в `gates`, правятся кнопками):
- `confluence_min`: 1 = выключено (по умолчанию), 2, 3;
- `confluence_window_min`: 5 / 10 (по умолчанию) / 30.

Источники совпадения — только отслеживаемые кошельки.

**Независимость:**
- Разные трейдеры, которые не являются одним человеком.
- Два адреса — один человек, если пересекаются их Solana-пары или один адрес встречается в паре другого.
- Один и тот же трейдер в разных сетях — один источник.

**Механика:**
- Буфер в памяти `self.pending[(uid, chain, token)] = [{source_id, label, ts, facts, trader}]`. Записи старше окна выбрасываются.
- Пока источников меньше порога: запиши сигнал с `decision='pending'` и без уведомления.
- Когда порог достигнут: обычный `judge()` по фактам **последнего** сигнала. Все фильтры применяются в этот момент, возраст сигнала считается от последнего. В `details` положи `confluence=[метки]`, `source='confluence'`. Уведомление: «🟢 КУПИЛ X — совпадение: A + B за N мин».
- Окно истекло, а порог не набран: `log_skip` с причиной `no_confluence`. Её можно заглушить кнопкой «🔕».
- Буфер общий для всех сетей; ключ включает сеть.

**Статистика:** позиции с `source='confluence'` сравнивай с одиночными в «📡 По источникам».

## Этап 4. Фильтр инсайдеров

Новый модуль `rhcopy/risk.py`:

```python
@dataclass
class RiskReport:
    chain: str
    token: str
    bundle_pct: float | None    # доля supply, скупленная пачкой на запуске
    dev_pct: float | None       # доля у создателя
    top10_pct: float | None     # топ-10 держателей без пулов, кривых и сжигания
    insider_pct: float | None   # доля у кошельков, связанных с создателем
    dev_rugs: int | None        # прошлые раги создателя (если источник знает)
    source: str                 # откуда данные
    notes: list[str]
```

**Провайдеры** (первый доступный, результаты объединяются):
1. **`MadeOnSolProvider`** (Solana, если есть `MADEONSOL_API_KEY`).
   - Токен-риск, бандлы (`/tokens/{mint}/bundle` по документации), репутация создателя.
   - Проверь по документации, что доступно на бесплатном тарифе. Ответы 402/403 означают «недоступно», а не ошибку.
2. **`SolanaHeuristics`** — встроенный.
   - Топ держателей через `getTokenLargestAccounts`. Владельцев определяй через `getMultipleAccounts`; аккаунты программ (пулы, bonding curve) и сжигание исключай.
   - Создатель — плательщик комиссии самой ранней транзакции минта.
   - Бандл — покупки в слоте создания и в 1–2 следующих слотах не от пула, в процентах от supply.
   - Ограничь число страниц `getSignaturesForAddress`. Если узел не поддерживает метод (PublicNode его режет) — поля `None`.
3. **`EvmHeuristics`** — встроенный, для Robinhood и Ethereum.
   - Создатель — `tx.from` первого `Transfer` от `0x0`. Блок создания ищи от `pairCreatedAt` DexScreener, `getLogs` кусками в пределах лимита провайдера.
   - Бандл — покупки в блоке создания пула и 2 следующих не от пула.
   - `dev_pct = balanceOf(deployer) / totalSupply`.
   - Топ держателей без индексатора не считай: только если задан `ETHERSCAN_API_KEY` (Etherscan API V2; проверь, какие сети поддерживаются).

**Кэш:** таблица `token_risk(chain, token, ts, report_json)`, TTL 30 минут. Метрики запуска со временем почти не меняются — бережём лимиты.

**Настройки пользователя** (в `gates`, кнопками в «🛡 Фильтры» → «🕵️ Инсайдеры»):
- `insider_check`: `off` / `soft` (по умолчанию) / `strict`. В режиме `soft` пропускаем только при доказанном нарушении. В режиме `strict` пропускаем ещё и когда данных нет.
- Пороги: `max_bundle_pct` 25, `max_dev_pct` 10, `max_top10_pct` 60, `max_insider_pct` 20, `skip_dev_rugger` true.

**Где проверять:** в `judge()`, после фильтров рынка и **до** котировок. Бюджет времени — 3 секунды. Если не уложились, действуй по режиму (`soft` → пропускаем проверку, `strict` → пропуск сигнала) и запиши примечание.

**Причины пропуска** с цифрами — добавь в `fmt.SKIP_RU` и `skip_detail`:
- `insider_bundle` — «на запуске пачкой скупили 34% (лимит 25%)»;
- `dev_holding`;
- `top10_concentration`;
- `insider_cluster`;
- `dev_rugger`;
- `risk_unknown`.

Добавь краткую строку риска в карточку позиции.

**Тесты:** юнит-тесты разборщиков на сохранённых JSON-ответах (`tests/fixtures/`), плюс одна живая проверка только на чтение на 2–3 известных токенах с отметкой `network`.

## Этап 5 (необязательно — только если этапы 1–4 готовы и тесты зелёные)

- **Крупная докупка = вход.** Трейдер докупает монету, которой у пользователя нет, на сумму от `gates.add_entry_min_usd` (по умолчанию 0 = выключено). Это считается сигналом входа с причиной `conviction_add`.
- **Выход зеркалом.** Новая настройка `exits.exit_style`: `all` (как сейчас) или `mirror`. В режиме `mirror` продаётся та же доля позиции, что продал трейдер. Доля = продано / баланс до продажи: для EVM баланс берётся на блок раньше, для Solana — из `pre/post` в `parse_trade`.

## Критерии приёмки

1. Все старые функции работают: Robinhood, Ethereum, Solana, несколько пользователей, кнопки, кошельки, вывод.
2. База и `config.yaml` от предыдущей версии открываются без ошибок. Миграционный тест проходит.
3. `python -m pytest -q` зелёный.
4. Обход кнопок проходит без ошибок для двух пользователей с импортированными трейдерами, включённым совпадением и фильтром инсайдеров.
5. Без `MADEONSOL_API_KEY` фильтр инсайдеров работает на встроенных эвристиках, а импорт MadeOnSol показывает «нужен ключ».
6. Новые функции не включают LIVE-сделки сами: режим (paper/LIVE) определяется только настройками пользователя, как раньше.
7. Живой прогон только на чтение `timeout 180 python main.py run` с тестовой базой — без ошибок в логе.
8. В коде нет Telethon и колл-каналов.
